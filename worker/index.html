Lviv public transport — GTFS feedsГромадський транспорт Львова — GTFS

Open, free GTFS Realtime feeds for trams, trolleybuses and buses in Lviv, Ukraine. Arrival times are predicted by our own machine-learning model, not copied from the timetable. No key, no sign-up.

TripUpdates — predicted arrivalshttps://eta.lad.lviv.ua/feed/trip_updates.pbGTFS-RT protobuf · refreshed about every 10 s
VehiclePositions — cleaned positionshttps://eta.lad.lviv.ua/feed/vehicle_positions.pbGTFS-RT protobuf · same refresh as TripUpdates
GTFS static — schedule, stops, shapeshttps://track.ua-gis.com/gtfs/lviv/static.zipPublished by the city operator; both realtime feeds are built against it

Quick start

pip install gtfs-realtime-bindings requests
import requests
from google.transit import gtfs_realtime_pb2

feed = gtfs_realtime_pb2.FeedMessage()
feed.ParseFromString(requests.get(
    "https://eta.lad.lviv.ua/feed/trip_updates.pb", timeout=10).content)

for e in feed.entity[:3]:
    tu = e.trip_update
    for stu in tu.stop_time_update:
        if stu.HasField("arrival"):
            print(tu.trip.trip_id, stu.stop_id, stu.arrival.time, "±", stu.arrival.uncertainty, "s")

Poll every 5–10 seconds. The files are served from Cloudflare's edge with Cache-Control: max-age=3, so polling faster returns the same bytes.

GTFS static

The schedule comes from the operator's feed (publisher: Львівавтодор). We don't modify it; the realtime feeds use its identifiers unchanged, so joins work directly. We check it every 5 minutes and switch to a new version within about half an hour of it being published.

FileWhat's in it

routes.txtAbout 70 routes. route_type 0 = tram, 3 = bus and trolleybus; trolleybus short names start with Тр, buses with А, trams with Т.
stops.txtAbout 1,000 stops. stop_id is the internal key; stop_code is the number printed on the stop sign.

calendar.txt, calendar_dates.txtService days.
feed_info.txtfeed_version and validity dates.

GTFS Realtime

Both feeds are GTFS-RT 2.0 FeedMessage protobufs (application/x-protobuf). The header timestamp is when the file was published.

TripUpdates

One entity per vehicle currently running a trip. Each lists predicted arrivals for up to the next 10 stops. The predictions come from a gradient-boosted model trained on months of archived vehicle positions. It uses live travel times from every other vehicle on the same street segments, dwell times at stops, and each vehicle's own recent pace. On held-out days the mean absolute error is about 93 s overall, and 61 s for the next stop.

FieldMeaning
trip.trip_id, start_date, start_time, direction_idExactly which run of which trip. Matches trips.txt.
vehicle.idThe vehicle making the prediction.
timestampWhen the GPS fix behind this prediction was taken. It can be up to 3 minutes old, while the header is always fresh.
stop_time_update[].stop_idMatches stops.txt stop_id (not the sign number).
arrival.timePredicted arrival, POSIX seconds. If the arrival time has already passed, the update says "arriving now" rather than being dropped.
arrival.uncertaintyExpected error in seconds, larger for stops further ahead. It is calibrated daily from the feed's live accuracy.
departure.timeArrival plus measured dwell: 32 s for trams, 27 s for buses and trolleybuses.
delayDeviation from the timetable, trams and trolleybuses only. Bus timetables are too far from reality for this to be useful.
Last update with NO_DATAMarks the end of the 10-stop prediction horizon. Don't carry delays past it to later stops.

VehiclePositions

The operator's positions, cleaned up and enriched:

  • Trip matching is corrected: each run goes to exactly one vehicle, with start_date/start_time, and it is the same trip that TripUpdates names.
  • stop_id and current_status (STOPPED_AT or IN_TRANSIT_TO) give the next stop.
  • congestion_level comes from observed speed compared with the usual speed for that route and hour.

Status

gtfs-eta.vbhjckfd.workers.dev/health returns JSON with HTTP 200 when the feed is fresh. It returns 503 if the feed is more than 3 minutes old, or if no arrivals are predicted at a central stop during service hours.

Terms

The feeds are free to use in apps, journey planners and research. Please keep polling to a reasonable rate and credit "lad.lviv.ua". The data comes with no warranty: predictions are estimates.

GTFS Realtime

Обидва фіди — protobuf FeedMessage за GTFS-RT 2.0 (application/x-protobuf). Час у заголовку — момент публікації файлу.

TripUpdates

Один запис на кожен транспорт, що зараз виконує рейс. У кожному записі — прогноз прибуття на щонайбільше 10 наступних зупинок. Прогноз дає модель градієнтного бустингу, навчена на місяцях архівних позицій транспорту. Вона враховує живий час проїзду інших машин тими самими відрізками вулиць, стоянку на зупинках і власний темп кожної машини. На відкладених днях середня абсолютна похибка — близько 93 с загалом і 61 с для найближчої зупинки.

ПолеЗначення
trip.trip_id, start_date, start_time, direction_idТочно який виїзд якого рейсу. Збігається з trips.txt.
vehicle.idМашина, для якої зроблено прогноз.
timestampКоли зроблено GPS-позначку, з якої пораховано прогноз. Вона може бути давністю до 3 хвилин, тоді як заголовок завжди свіжий.
stop_time_update[].stop_idЗбігається зі stop_id у stops.txt (а не з номером на табличці).
arrival.timeПрогноз прибуття, секунди POSIX. Якщо час прибуття вже минув, запис каже «прибуває зараз», а не зникає.
arrival.uncertaintyОчікувана похибка в секундах, більша для дальших зупинок. Щодня калібрується за фактичною точністю фіду.
departure.timeПрибуття плюс виміряна стоянка: 32 с для трамваїв, 27 с для автобусів і тролейбусів.
delayВідхилення від розкладу, лише трамваї й тролейбуси. Автобусний розклад надто далекий від реальності, щоб це поле було корисним.
Останній запис із NO_DATAПозначає кінець горизонту прогнозу в 10 зупинок. Не переносьте затримку за нього на дальші зупинки.

VehiclePositions

Позиції оператора, очищені й доповнені:

  • Прив'язку до рейсу виправлено: кожен виїзд належить рівно одній машині, з start_date/start_time, і це той самий рейс, що й у TripUpdates.
  • stop_id і current_status (STOPPED_AT або IN_TRANSIT_TO) вказують наступну зупинку.
  • congestion_level — з порівняння фактичної швидкості зі звичною для цього маршруту й години.

Стан

gtfs-eta.vbhjckfd.workers.dev/health повертає JSON із HTTP 200, коли фід свіжий. Він повертає 503, якщо фіду понад 3 хвилини, або якщо в години руху немає прогнозів для центральної зупинки.

Умови

Фіди можна вільно використовувати в застосунках, планувальниках поїздок і дослідженнях. Будь ласка, опитуйте помірно й зазначайте «lad.lviv.ua». Гарантій немає: прогнози — це оцінки.
